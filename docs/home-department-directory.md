# 홈페이지 학과별 연구실 탐색 (TTOK-65)

홈의 예시 목록을 단과대·학과별 연구실 개수 API로 교체했다. 실제 개수와 학과 검색 결과로 이어지는 탐색 흐름을 제공한다.

- `GET /api/laboratory/college-department/count`: 단과대·학과의 코드, 한글 명칭, 연구실 개수. 서버 단과대 순서를 유지하고 학과는 개수 내림차순으로 정렬한다. 같은 개수는 서버 순서를 유지한다.
- 0개 학과와 빈 단과대는 숨긴다. 카드별 3개 학과를 먼저 표시하며 `+N개 학과 더보기`로 전체 학과를 펼치고 접을 수 있다.
- 긴 학과명은 한 줄 말줄임을 사용하며 전체 명칭은 링크의 접근 가능한 이름과 title에 보존한다.
- 학과 링크는 `/search?department=한글학과명`으로 이동한다. enum 코드를 검색 파라미터로 사용하지 않는다.
- 학과 검색·학과 내 키워드 검색을 지원한다. 페이지 이동, 새로고침, 직접 URL에서도 조건을 보존한다. 상위 분야와 학과의 조합은 별도 카테고리 API 계약 때문에 차단한다.
- 섹션은 Suspense로 별도 로딩하며 조회 실패가 홈 전체를 가리지 않는다. 오류 시 다시 시도로 router.refresh를 호출하고 정상 빈 목록과 오류를 구분한다. 실패 시 목데이터·임의 개수를 표시하지 않는다.
- 데스크톱의 기존 Home 배치에 통합했다. 768px 이상 2열, 1280px 이상 4열이다. 768px 미만 Home은 기존 모바일 탐색 UI를 유지한다.
- 드롭다운의 기존 예시 단과대·학과 목록 전체 교체는 이번 범위에 포함하지 않는다. 검색 조건 연결은 기존 공통 함수를 확장했다.

## 검증

- 개수 정렬·0개 제외·잘못된 응답 구분과 URL/API 조건 매핑 테스트 8개
- 타입 검사, lint, Next 빌드, Storybook 빌드
- Storybook 정상·로딩·오류·빈 목록·학과 1개·펼치기/접기 상태
- 실제 API의 9개 단과대·30개 학과: 개수와 검색 결과 총 개수/학과 일치
- 키보드 Enter로 더보기, 접기, 실제 학과 검색 이동·새로고침·뒤로 가기
- 320/375/768/1440px 가로 넘침 확인

서버가 제공하는 명칭과 개수를 사용하므로 디자인 예시의 인공지능대학 대신 현재 응답의 정보기술대학 등이 표시된다. 개수 API는 5분 재검증, 검색은 캐시하지 않으므로 데이터 갱신 직후에는 차이가 날 수 있다.


## 홈 탐색 보정 · TTOK-75 (2026-10-09)

- 홈 조회는 기존 size=6 요청을 유지하되 서버가 더 큰 페이지를 반환하더라도 첫 6개만 반환한다. 데스크톱·모바일 홈에 공통 적용한다. 서버 기본 순서를 유지하며 검색 결과에는 적용하지 않는다.
- 홈 검색바 아래 추천 검색어 Chip을 제거한다. 홈의 빈 검색 입력 검증은 유지한다.
- 공통 헤더의 메뉴 문구를 ‘연구실 탐색’으로 통일한다.
- 단과대 제목은 collegeName으로 전체 검색, 학과명은 departmentName으로 학과 검색을 연결한다. 더보기는 별도 버튼으로 유지한다.
- 카드 기본 최소 높이는 240px. 학과 링크 hover/focus에서 이름만 SemiBold·기본 텍스트 색상으로 강조하고 개수는 Regular·subtle 상태를 유지한다. 확장 시 내용에 맞게 카드가 늘어난다.
- 브라우저 검증: 데스크톱·375px 모바일 홈 카드 6개, 공과대학 전체 90개/페이지 카드 20개 유지, 포커스 이름 600·개수 400 확인.
- 타입 검사·lint·앱 빌드·Storybook 빌드·기존 테스트 22개 통과. ExpandAndCollapse play에서 단과대 href와 더보기/접기 회귀 확인 및 콘솔 오류 없음.
